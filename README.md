# Тестовое задание

## Tunduk Dashboard

Рабочий dashboard для HR-специалиста, который позволяет просматривать кандидатов, фильтровать и сортировать список, открывать детальную карточку и менять статус обработки резюме

## Что реализовано

- список кандидатов с поиском по ФИО, фильтрацией по решению, сортировкой, пагинацией и сохранением состояния в URL
- детальная страница кандидата с контактами, summary, опытом, образованием, стеком, критериями оценки и вопросами для собеседования
- смена статуса кандидата через mock PATCH с optimistic update, rollback при ошибке, loading state и toast/snackbar уведомлениями
- unit и integration тесты на ключевые сценарии
- поддержка большого mock-набора данных с виртуализацией рендера списка

## Принятые решения

- состояние фильтров, поиска, сортировки и пагинации хранится в URL query params, чтобы список был восстанавливаемым и ссылкоустойчивым
- для управления кандидатами используется Zustand, а mock API слой изолирован в `src/services`
- смена статуса сделана через optimistic update в store с защитой от stale rollback
- для уведомлений о смене статуса используется внешняя библиотека `sonner`, а не самописный toast
- по умолчанию приложение работает на `mock/candidates-large.json`, чтобы основной сценарий сразу проверялся на длинном списке и нагрузочном режиме
- виртуализация сделана через `react-window`, при этом пагинация по 10 кандидатов на страницу сохранена в соответствии с ТЗ

## Компромиссы

- исходное ТЗ для заданий 1–4 предполагает основной small mock на 25 кандидатов, но в этой реализации дефолтный источник переключён на large mock как осознанное расширение решения
- small mock сохранён в кодовой базе и может использоваться через mock API слой, но отдельный пользовательский переключатель между наборами данных не добавлялся
- виртуализация встроена в рендер списка при сохранённой пагинации, поэтому основной выигрыш проявляется не как бесконечный scrolling feed, а как production-ready стратегия рендера для длинного датасета

## Что не успели сделать

- отдельный UI-переключатель между `mock/candidates.json` и `mock/candidates-large.json`
- отдельный performance-профайлинг или метрики рендера поверх базовой виртуализации

## Структура проекта

- `src/pages` — страницы списка и карточки кандидата
- `src/components` — UI-блоки списка и detail page
- `src/store` — Zustand store и optimistic update логика
- `src/services` — mock data и mock API
- `src/utils` и `src/hooks` — вспомогательная логика, query params, debounce
